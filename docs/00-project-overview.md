# 00 · 项目概览

> 性质：范围声明与文档导航，**不新增任何契约**。契约唯一事实来源是 02（架构）/03（模块）/04（数据库）/05（API）/13（主页空间）。
> 引用格式：`§<节> 第 <行号> 行`，行号为本文件写作时实测（可用 `(Get-Content <file>).Count` 复核）。

## 1. 一句话定位

Legere 是一款单人本地使用的 PDF 文献库阅读器：在一个完全离线的 Windows 桌面应用里，把「本地文献库管理 + 中文库级全文检索 + 完全自定义的阅读界面」三件事装在一起。

技术栈已冻结，不重新讨论：Tauri 2 · Rust · React + TS + Vite · pdfjs-dist（**仅 Display API**）· SQLite + FTS5 · jieba-rs · Tokio · notify · Zustand · Tailwind（见 02 §1 第 8–22 行）。

## 2. 目标用户

只有一名：项目作者本人，在自己的机器上管理自己的 PDF 文献。

- 单实例、单用户、无账号、无网络同步：见 02 §11 D12（第 302 行）。
- 数据只落两处：本地 PDF 文件 + 本地 SQLite；索引、书签、进度、设置全在库里（_shared-context.md A 节第 9–13 行）。
- 不面向团队、不面向分发、不需要多设备一致性；因此一切「同步冲突」「权限模型」「多人编辑」类需求都不进入本项目。
- 但**单人 ≠ 可以粗糙**：崩溃、数据不一致、读不了自己存的文献，是这个产品唯一不可接受的故障（master_plan.md §4.2 第 312–327 行）。

## 3. 三个真实痛点

| # | 痛点 | 现状后果 | 本项目对应的能力 | 依据 |
|---|---|---|---|---|
| P1 | 只记得「某篇里有一句话」，不记得文件名 | 只能逐个打开 PDF 用阅读器查找，找到之前不知道该开哪一篇 | 页面级 FTS5 索引 + 库级检索，返回「文档 / 页码 / 上下文 / 命中区间」 | 02 §7 第 214–231 行；04 §7 第 184–188 行 |
| P2 | 现成阅读器的界面结构不可改（固定工具栏 + 固定侧栏 + 固定分栏） | 阅读区被长期压缩，交互要迁就别人的布局 | 只用 pdfjs-dist Display API 取字节/渲染/文本/Outline，UI 全部自建，L4/L3/L2 三层分离 | 02 §11 D02（第 292 行）；master_plan.md §3.2 第 112–140 行 |
| P3 | 大文件加载与后台建索引互相拖累 | 打开大 PDF 卡顿；或建索引时整机发烫、阅读掉帧 | pdf:// 自定义协议 + Range 流式按需取字节；只渲染可视区与预取窗口；后台提取独立线程池 + 批间主动让位 | 02 §11 D01（第 291 行）；02 §9 第 266–277 行 |

## 4. 与常见 PDF 阅读器的差异

只列本项目**确实有能力兑现**的差异；不写「更快更智能」这类无法验收的表述。

| 维度 | 常见 PDF 阅读器 | Legere | 兑现依据 |
|---|---|---|---|
| 界面结构 | 顶部固定工具栏 + 内置 Viewer 组件即 UI | 不采用 PDF.js Viewer 的 UI，阅读界面由 React 自建，Scheduler 与 React 组件解耦 | D02（02 第 292 行）；03 M06/M07 第 84–104 行 |
| 库级检索 | 单文档内查找为主；跨文档检索多为文件名匹配或对中文不友好的分词 | 页面级 FTS5 + jieba 精确模式预分词，库级命中带页码、原始文本上下文与字符区间 | D04/D05（02 第 294–295 行）；04 §7 |
| 入口形态 | 文件列表 / 缩略图网格 | 书脊沿圆周排布的空间转盘：可见弧完整渲染并可交互，隐藏弧**零 DOM** | 13 §2 第 46–50 行 |
| 数据边界 | 常见形态是账号 + 云同步 + 在线 OCR | 无账号、无网络、无上传；断网全功能可用 | D12（02 第 302 行） |
| 内存与渲染 | 整篇/大块渲染，切文档常靠重开文件 | pdf:// + HTTP Range 分段；可视区 + 预取窗口；渲染并发默认 2；Canvas LRU 按字节预算逐出 | D01（02 第 291 行）；02 §9 第 274 行；03 M06 第 86 行 |
| 功能野心 | OCR / 注释 / 签名 / 表单 / 协作 | 明确不做（见 §6），复杂度全部投在检索质量与阅读流畅度上 | D11（02 第 301 行）；master_plan.md §3.2 第 125–126 行 |

## 5. 产品原则（每条附可判定判据）

| 原则 | 判据（可核查，不是口号） |
|---|---|
| Local-first | 断网启动后全部功能可用；代码中不存在任何指向远程服务的 HTTP 客户端；`app_info` 返回的 `dataDir`/`dbPath` 是唯一数据落点（05 §3 第 173 行） |
| 阅读优先 | 后台任务不是被抢占，而是在**每批之间**检查 `index_pause` 与「是否出现更高优先级任务」，出现即主动让位（02 §9 第 277 行） |
| 索引不阻塞阅读 | 写走单写连接串行队列 + WAL 只读连接（04 §2 第 22 行）；索引写事务以 8 页一批提交（02 §6 第 210 行）；提取信号量上限 2（02 §9 第 272 行） |
| UI 由用户拍板 | 一切视觉/交互数值进「【待你确认】」清单，模块实现留 `TODO(ui-confirm)` 并在交付报告逐条列出（_shared-context.md F 节第 63–70 行） |
| 不过度设计（YAGNI） | 首版范围只有 01 §1.4 的 F 清单；未列入 F 的功能不写代码；契约未定义的表、列、Command、事件一律不新增（05 §3 第 201–206 行约束） |

## 6. 明确不做

| 不做 | 理由与依据 |
|---|---|
| OCR / 扫描件文字识别 | D11（02 第 301 行）；提取不到文本即 `text_state=no_text` 并停止重试（02 §6 第 211 行） |
| 注释 / 批注 / 签名 / 表单填写 | master_plan.md §3.2 第 125–126 行明确不需要 |
| 云同步 / 账号 / 多设备 | D12（02 第 302 行） |
| 多人协作 / 共享文献库 | 单人产品（§2） |
| 插件系统 / 脚本扩展 | 与 YAGNI 冲突，且无任何接口稳定性承诺可对外 |
| PDF 编辑、格式转换、导出 | 不在 master_plan.md §3 任何小节内 |
